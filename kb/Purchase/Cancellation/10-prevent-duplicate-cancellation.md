# 避免重複取消與重複作廢

取消採購、撤銷簽核或發票作廢屬於具狀態性的操作。系統應先檢查目前狀態，再決定是否允許再次執行，避免重複送出造成資料不一致。

## 防護原則

1. 每次操作前讀取最新 PO、Approval 與發票狀態。
2. 已取消的採購單不得再次取消。
3. 已撤回的 Approval 不得重複撤回。
4. 已作廢的發票不得再次送出作廢。
5. 呼叫外部電子發票服務後，應保存請求識別碼與回應結果。
6. 若發生逾時，不應直接重送，應先查詢前一次交易是否已成功。

此原則可降低重複 API 呼叫、重複憑證異動與人工對帳成本。
