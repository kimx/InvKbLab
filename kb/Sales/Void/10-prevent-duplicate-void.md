# 避免重複作廢與重複開立

發票作廢、重開與折讓都屬具狀態性的操作。系統在重送前應先查詢目前狀態，避免因逾時或重試造成重複異動。

## 防護原則

1. 每次異動前讀取最新發票狀態。
2. 已作廢的發票不得再次作廢。
3. 作廢成功後才建立新的重開發票。
4. API 呼叫保存交易識別碼、請求時間與回應。
5. 發生逾時時先查詢前次結果，不直接再次送出。
6. 訂單、發票與異動紀錄應建立可追溯關聯。

此設計可降低重複發票、重複作廢與人工對帳風險。
